# `poc/` — one-shot Pingora capability probes

**Status: throwaway asset.** Nothing here is a contract, a library, or a candidate for
`crates/`. The directory exists to answer, against the locked `pingora 0.9.1` and this machine,
the questions that block `nico-http` design. When the answers are recorded in
[`FINDINGS.md`](./FINDINGS.md) and the phase-0 report, this directory is deleted.

Read [`FINDINGS.md`](./FINDINGS.md) first; it is the deliverable. The code only exists so every
claim in it can be reproduced.

## Layout

```text
poc/
├── Cargo.toml              # independent [workspace]: members = ["spikes"]
├── Cargo.lock              # committed: probe results are only meaningful for these versions
├── rust-toolchain.toml     # 1.99.0, same as the product workspace
├── README.md
├── FINDINGS.md             # evidence table + "still needs re-verification"
├── scripts/
│   ├── run-probes.sh       # runs all ten probes, writes .evidence/
│   └── ws_client.py        # stdlib-only RFC 6455 client (curl cannot speak WebSocket)
├── spikes/
│   ├── Cargo.toml
│   └── src/
│       ├── lib.rs          # hand-written HTTP/1 framing, sha256, WebSocket accept
│       └── bin/
│           ├── spike-mock.rs   # tokio TCP upstream: h1, h2c, SSE, flood, WS, gRPC trailers
│           └── spike-http.rs   # Pingora proxy with instrumentation on every hook
└── .evidence/              # generated by run-probes.sh, not committed
```

## Pinned versions

| Crate | Version | Note |
|---|---|---|
| `pingora` | `=0.9.1` | features `proxy`; default features are empty, `proxy` must be enabled |
| `pingora-core` | `=0.9.1` | direct dep for `Digest`/`ServerConf` types |
| `tokio` | `=1.54.1` | `rt-multi-thread,net,time,sync,signal,macros,io-util` |
| `h2` | `=0.4.20` | mock upstream only: raw HTTP/2 so gRPC trailers can be produced |
| `http` | `=1.5.0` | header types for the `h2` server |
| `bytes` | `=1.12.1` | |
| `sha2` | `=0.10.9` | body digests |
| `async-trait` | `=0.1.92` | `ProxyHttp` impl |
| `tracing` / `tracing-subscriber` | `=0.1.44` / `=0.3.23` | structured, timestamped probe logs |

`hyper`, `axum`, `reqwest` are deliberately absent: the mock must expose raw bytes and
connections, and HTTP clients are `curl 8.7.1` (nghttp2) plus the stdlib Python WebSocket client.

## Build prerequisites

- macOS arm64 (this run), Rust `1.99.0`.
- **`cmake` on `PATH`.** `pingora-core 0.9.1` depends on `flate2` with the `zlib-ng` feature, which
  builds `libz-ng-sys` through CMake 3.x. Without it the build fails in `build-script-cmake`
  ("is `cmake` not installed?"). `brew install cmake` was required on this machine.
- TLS is **not** needed for anything in this PoC. Plaintext HTTP/2 (`h2c`) is a server option, not
  a Cargo feature. For the record, `--features boringssl` also builds on this machine in ~45 s
  (CMake present) but no TLS listener was exercised.

## Run

```bash
cd poc
cargo build --release --all-features     # must pass before any claim is valid
cargo test  --all-features               # 2 unit tests: RFC 6455 accept value, base64 padding

./scripts/run-probes.sh                  # all ten probes; evidence in ./.evidence
OUT=/tmp/pingora-evidence ./scripts/run-probes.sh
```

Ports: gateway `18080`, mock `18081`, four-worker instance `18082`, graceful-shutdown instance
`18084`. The script starts and kills its own processes; if it is interrupted:

```bash
pkill -f 'target/release/spike-http'
pkill -f 'target/release/spike-mock'
```

Probes can also be run by hand (both binaries are env-configurable):

```bash
SPIKE_MOCK_ADDR=127.0.0.1:18081 ./target/release/spike-mock
SPIKE_LISTEN=127.0.0.1:18080 SPIKE_UPSTREAM=127.0.0.1:18081 \
SPIKE_GRACE=3 SPIKE_THREADS=1 ./target/release/spike-http
```

## What the spikes do (and do not do)

- `spike-mock` writes HTTP/1.1 and h2c by hand. It logs every request head, connection accept,
  body digest, SSE write timestamp, flood progress, WebSocket frame, and h2 trailer.
- `spike-http` logs every `ProxyHttp` hook with `t_ms`, elapsed time, chunk sizes, downstream
  protocol, worker thread id, and the upstream connection's `reused` flag.
- Neither binary implements routing, config, TLS, or production error handling. `spike-http`
  hard-codes a single upstream and selects h2 upstream only for `/grpc`.
