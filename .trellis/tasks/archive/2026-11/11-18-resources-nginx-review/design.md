# 技术设计：资源配置 nginx 对齐审查

## 1. 目标与不变量

本任务交付可供决策的资源配置审查：说明现有 YAML 能表达什么、与 nginx 在哪些条件下对应，以及哪些差异会改变迁移后的请求行为。

1. 现行行为以源码和行为测试为依据，nginx 行为以官方文档为依据；旧调研只能作为待核实线索。
2. 概念对应、语义等价、算法兼容分别判断。共同使用一个名称，不足以推出后两者。
3. 配置归属保持清楚：bootstrap 管进程、监听及配置获取；resources 管路由、上游、provider 与策略。listener 不自动等于虚拟主机。
4. 调整建议必须绑定具体请求场景、用户收益、兼容性代价和验证方法；不根据表面相似度增加字段或层级。
5. 审查不改变现行产品契约。任何 schema 或运行行为调整都需要用户明确选择，并以独立实施边界规划。

## 3. 审查模型

每行对应关系回答五个问题：

- nginx 指令/上下文表达哪件事实？
- nico 哪个字段/运行阶段消费这一事实？
- 什么条件下能保留用户可见的行为？
- 条件不成立时，给一个能区分两者的请求或配置反例。
- 结论是保留命名、补充说明、候选重命名，还是独立能力缺口？

采用以下判断词汇：

| 判断 | 使用条件 |
|---|---|
| 可直接映射 | 所列前提下相关可见行为一致，未暗示整体产品兼容 |
| 条件映射 | 目标相近，但默认值、作用域、算法或请求处理存在差异，迁移必须显式调整 |
| 无直接对应 | 现有公开配置不能表达该能力；内部扩展 trait 不算部署者已能配置 |
| 文档表述问题 | 文档或示例与当前代码不符；单独记录，不能伪装成 schema 新需求 |

## 4. 核查维度

### 路由

核对 host 规范化和限定 host 优先级、path 的比较输入、相同匹配条件的发布期行为、query 是否参与、listener 是否参与选择。nginx 对照包括 listen/server_name 两阶段、location 的规范化/精确/正则/尾斜杠行为、proxy_pass URI 替换。

至少区分：同 host 不同前缀、限定 host 与通配路由交叠、host 命中但路径缺席、多个 listener、`/api` 与 `/api/`、`/apix`、编码路径和 query。

### 上游

连接目标、逻辑 authority、Host、TLS SNI 分别追溯。按策略核对默认选择、权重何时消费、活跃数是请求还是连接、IP 键来源和算法。健康核对失败分类、连续失败与时间窗口、冷却探测、单成员行为、全部剔除以及 reload 状态继承。

普通 traffic 的换成员与 LLM provider 的 retry/fallback 分开描述；不能将已有 LLM 弹性误写成普通代理已具有 nginx proxy_next_upstream。

### 策略

区分实例声明与引用位置；明确 global 与 route 的阶段、顺序、认证建立身份的时点、enabled 的影响及请求 body 缓冲的作用范围。限流核对算法、burst 含义、默认拒绝码、键和状态作用域；认证核对 bearer/key 与 Basic/子请求的边界。

### 限制与缓冲

核对文档总值和路由值的覆盖/收紧规则，不能将所有字段统一声称为继承或总上限。分别描述总 deadline、单次 I/O 等待、请求缓冲、LLM 非流式响应缓冲和普通代理转发。单独列出数值 0、单位和默认值的迁移风险。

## 5. 建议的形成

建议按用户误配影响和实施代价排序：

- 说明或示例即可解决的误解：建议具体修改位置与文案事实；本任务输出建议。
- 名称暗示错误语义：评估重命名是否真正减少误解，列出需要迁移的 YAML、代码、错误、spec 和测试；本任务不预先采用新名称。
- 缺失能力：记录一个真实部署场景、现有边界和验证目标，交由后续任务决定，不把 nginx 全功能兼容作为本次要求。

每项建议附可观察的验收方式，保留 traffic/llm role、原子发布与 LKG、在途 generation、凭证引用和显式资源边界等现有约束。

## 6. 兼容性与失败处理

审查阶段不改变运行行为、不引入依赖、不生成新的有效 schema。因此现有配置与二进制兼容性不受本任务影响；验证对象是结论的准确性。

官方资料无法访问或源码/测试无法证明的断言必须标为未验证，并给验证方法。发现潜在代码缺陷时只记录最小证据与影响，不在规划中直接修复；若改变本任务范围，先更新 PRD 并重新收敛。

## 7. 运行、验证与回退

只运行与结论相关的既有测试（必要时），记录命令和结果；没有实际执行的测试只能称为静态证据。纯任务文档变更无需以全量 Rust 构建冒充本轮验证。

任务清单通过 `task.py validate`，新增文档通过 whitespace 与引用位置检查，最终 diff 必须只包含本任务目录。回退只涉及本任务记录，产品代码和 binding spec 无需回滚。

完整迁移指南 `docs/nginx-migration.md`、schema 变更和新增代理能力属于后续独立交付。

## 8. 已识别的审查风险

- 路由 `timeout_ms` 写大于文档值时可解析，但 runtime 会取两者较小值；示例 120000/30000 只能产生 30 秒总预算。报告必须区分“可解析”和“实际生效”。
- 插件请求整体缓冲只扣 body，请求头先发；convert 非流式响应另有 bounded buffer。不能将插件接口限制写成全网关不缓冲。
- global auth 可为同 scope 随后的限流建立 subject；“全局没有路由 id”不代表“全局全过程没有身份”。该场景当前以调用链推导为证，未声称有专门 E2E。
- `providers[].timeout_ms` 在初步研究中未找到运行时消费者；报告需保留“待确认”标记和核查位置，不把它写成已复现缺陷或擅自移除字段。
- 特殊 URI 的完整框架解析矩阵、DNS 动态行为和 nginx 实进程差分尚未执行；结论限定在已核实的消费路径和官方文档语义。
